# Безбедност на системот

Безбедноста во овој систем не е надворешен додаток, туку дел од самата архитектура — секој слој (frontend, backend, база) учествува во заштитата на податоците и контролата на пристапот. Наместо да се потпира на едно решение, системот комбинира неколку независни механизми кои заедно го намалуваат ризикот од неовластен пристап, манипулација на податоци или загуба на информации.

### Хеширање на лозинки

Лозинките никогаш не се чуваат како чист текст во базата — се хешираат со алгоритмот **bcrypt** пред да се зачуваат:

```py
# backend/password_utils.py
def hash_password(plain: str) -> str:
    return bcrypt.hashpw(plain.encode("utf-8"), bcrypt.gensalt()).decode("utf-8")

def verify_password(plain: str, stored) -> bool:
    if stored.startswith("$2") and len(stored) > 50:
        return bcrypt.checkpw(plain.encode("utf-8"), stored.encode("utf-8"))
```

При најава, системот не ja дешифрира лозинката (bcrypt е еднонасочен), туку повторно ja хешира внесената лозинка и ги споредува хешевите. bcrypt е намерно бавен по дизајн — секое повикување одзема милисекунди наместо микросекунди, што значи дека дури и ако некој дојде до содржината на базата, погодувањето на лозинки преку груба сила (brute-force, милиони комбинации во секунда) станува практично невозможно во разумно време.

### Правила за лозинка на лекари

За разлика од пациентите, кои сами си ja бираат лозинката при регистрација, лекарите не се регистрираат самостојно — администрацијата им креира сметка со привремена лозинка. Backend-от наметнува строга валидација при првата промена: минимум 8 знаци, барем една голема буква, еден број и еден интерпункциски знак. Додека привремената лозинка не биде заменена, пристапот до целосниот лекарски панел е ограничен — со цел да се спречи долготрајно користење на лесно погодлива, системски генерирана лозинка.

### Сесии со истек

`fontend/session.js` управува со траењето на најавата преку timers на клиентската страна:

| Правило          | Вредност        | Цел                                                                                                                                              |
| ---------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Неактивност      | 5 минути        | Доколку корисникот не прави ништо 5 минути, нема никаква активност- се одјавува автоматски                                                       |
| Максимален лимит | 8 часа          | Дури и при непрекината активност, по 8 часа мора повторна најава. Ова се однесува на лекарите тие голем дел од времето би го минувале на сајтот. |
| Предупредување   | 30 секунди пред | Toast известување со копче „Остани најавен"                                                                                                      |

Овој механизам ja намалува изложеноста на профилот доколку корисникот заборави да се одјави на заеднички или јавен компјутер — сесијата автоматски истекува наместо да остане отворена неограничено.

### Клучни кодови за сесијата

#### Конфигурација — временски лимити

```js
var INACTIVITY_TIMEOUT_MS = 5 * 60 * 1000;     // 5 минути неактивност
var ABSOLUTE_TIMEOUT_MS   = 8 * 60 * 60 * 1000; // 8 часа од најава
var WARN_BEFORE_MS        = 30 * 1000;          // предупреди 30 секунди пред
var TICK_INTERVAL_MS      = 10 * 1000;          // проверка секои 10 секунди
```

Ги дефинира четири временски константи кои го одредуваат однесувањето на сесијата.

Двата независни тајмери (5 минути и 8 часа) работат паралелно и спречуваат две различни безбедносни закани — заборавена сесија на заеднички компјутер и бесконечно отворена сесија при долги смени. 30-секундното предупредување дава време за реакција без да ја наруши безбедноста. 10-секундниот tick е баланс помеѓу прецизност и перформанси.

#### Wrapper формат за чување податоци

```js
function readWrapped(key) {
    var raw = sessionStorage.getItem(key) || localStorage.getItem(key);
    var parsed = safeParse(raw);
    if (!parsed) return null;
    if (isWrapped(parsed)) return parsed;
    // Стар (не-завиткан) формат → завиткај го со „now" timestamps
    return {
        data: parsed,
        loggedInAt: now(),
        lastActivityAt: now()
    };
}

function writeWrapped(key, wrapped) {
    var s = JSON.stringify(wrapped);
    sessionStorage.setItem(key, s);
    localStorage.setItem(key, s);
}
```

`readWrapped` чита податоци од storage и проверува дали се во новиот wrapper формат (со timestamp-ови). Ако се во стар формат, автоматски го завиткува. `writeWrapped` ги запишува во **и** `sessionStorage` **и** `localStorage`.

Чувањето во два storage-а е критично за безбедност — ако едниот се исчисти (на пример, `sessionStorage` при затворање на таб), `localStorage` го задржува податокот за cross-tab синхронизација. Wrapper-от додава метаподатоци за следење на времето без да се наруши постоечката структура на податоците.

#### Проверка на истек на сесија

```javascript
function checkExpiry(wrapped) {
    if (!wrapped) return null;
    var t = now();
    if (t - wrapped.loggedInAt > ABSOLUTE_TIMEOUT_MS) return 'absolute';
    if (t - wrapped.lastActivityAt > INACTIVITY_TIMEOUT_MS) return 'inactivity';
    return null;
}
```

Пресметува дали сесијата истекла според два услови: времето од најава и времето од последна активност.

Ова е срцето на безбедносниот механизам. Проверува прво апсолутниот лимит (8 часа), потоа неактивноста (5 мин). Враќа стринг кој ја кажува причината — ова се користи за точно известување на корисникот зошто е одјавен. Ако `wrapped` е `null`, враќа `null` — нема сесија, нема што да истече.

#### Периодична проверка (tick)

```js
function tick() {
    [['pacient', KEY_PACIENT], ['lekar', KEY_LEKAR]].forEach(function (pair) {
        var role = pair[0], key = pair[1];
        var wrapped = readWrapped(key);
        if (!wrapped) return;

        var expiry = checkExpiry(wrapped);
        if (expiry) {
            endSession(role, 'expired');
            showExpiredNotice(role, expiry);
            return;
        }

        var remaining = msUntilExpiry(wrapped);
        if (remaining <= WARN_BEFORE_MS && !warnShownFor[role]) {
            warnShownFor[role] = true;
            showWarningToast(role, remaining);
        }
    });
}
```

Се повикува секои 10 секунди. За секоја активна сесија проверува дали истекла — ако да, ја брише и покажува известување. Ако не, проверува дали останало помалку од 30 секунди и прикажува предупредување.

Event listener-ите (клик, тастатура) го освежуваат `lastActivityAt`, но ако корисникот воопшто не прави ништо (отворил таб и заминал), ниту еден event нема да се случи.&#x20;

`tick()` е единствениот механизам кој открива дека поминале 5 минути без активност и ја извршува одјавата. Без ова, сесијата би останала отворена неограничено.

#### Одјавување и чистење

```js
function endSession(role, reason) {
    var key = role === 'lekar' ? KEY_LEKAR : KEY_PACIENT;
    clearKey(key);
    warnShownFor[role] = false;
    if (!hasAnyActiveWarning()) hideWarningToast();

    window.dispatchEvent(new CustomEvent('kbs:session-end', {
        detail: { role: role, reason: reason || 'manual' }
    }));
}

function clearKey(key) {
    sessionStorage.removeItem(key);
    localStorage.removeItem(key);
}
```

`endSession` ја брише сесијата од **два** storage-а, ги трга известувањата, и испраќа custom event за синхронизација со остататата апликација.

Чистењето од двата storage-а е критично — ако се избрише само од едниот, податокот останува и сесијата technically се уште постои. `CustomEvent` го известува `script.js` да ги ресетира внатрешните променливи и да ја прикаже страницата за најава. `reason` параметарот овозможува разликување на рачна од автоматска одјава

#### &#x20;Слушатели на активност со throttle

```js
function attachActivityListeners() {
    var lastTouch = 0;
    var THROTTLE_MS = 5000;
    function throttledTouch() {
        var t = now();
        if (t - lastTouch < THROTTLE_MS) return;
        lastTouch = t;
        touchActivity();
    }

    var events = ['mousemove', 'mousedown', 'keydown', 'scroll', 'touchstart', 'click'];
    events.forEach(function (ev) {
        document.addEventListener(ev, throttledTouch, { passive: true });
    });
}
```

Поставува слушатели за шест типа на корисничка интеракција. Секој слушател е throttle-нат — активноста се регистрира најмногу еднаш на 5 секунди.

Без throttle, `mousemove` се пука стотици пати во секунда, а секој повик чита и пишува во `localStorage` — што е споро и го оптеретува браузерот. `passive: true` кажува на браузерот дека нема да се повика `preventDefault()`, што овозможува подобри перформанси при скролирање (особено на мобилни). Шесте различни events покриваат сите начини на интеракција — со глувче, тастатура, допир, скрол.

#### Синхронизација при враќање на табот

```js
document.addEventListener('visibilitychange', function () {
    if (document.visibilityState === 'visible') tick();
});
window.addEventListener('focus', tick);
```

Кога корисникот се враќа на табот или прозорецот, веднаш ја повикува `tick()` за проверка.

Доколку корисникот остане на друг таб 6 минути, `tick()` не се повикувал во оригиналниот таб. Кога се враќа, `visibilitychange` се пука и `tick()` веднаш открива дека сесијата истекла (5 мин неактивност) и ја извршува одјавата. Без ова, корисникот би останал „најавен" на страната иако сесијата е истечена.

### Валидација на влез

Секој router спроведува строги проверки пред да зачува податок во базата — ЕМБГ мора да содржи точно 13 цифри и да биде единствено, е-поштата мора да помине формат-проверка и да не постои веќе во базата, а датум и време се нормализираат (на пример `9:5` → `09:05`) пред да се зачуваат. Овие проверки спречуваат невалидни, дуплирани или потенцијално опасни податоци да навлезат во системот низ обичен кориснички внес.

### Сопственост на податоци

При секоja чувствителна акција над термин — оценување, откажување или пренос — backend-от ja споредува е-поштата зачувана во сесијата/токенот на корисникот наспроти е-поштата зачувана на самиот термин во базата. Доколку не се совпаѓаат, се враќа грешка **403 Forbidden**, и акцијата не се извршува. На овој начин, дури и ако корисник А некако дојде до ID на термин на корисник Б, нема начин да го прегледа или измени без да биде најавен токму како тој корисник.

Со користењето на овие механизми се обидуваме да ја подобриме безбедноста на нашите корисници, од пациенти до лекари кој секојдневно голем дел од работното време го поминуваат овде, на овој сајт.
